How a drawing is found

The search: rows, moves and kicks

scav does not lay a chart out once. It lays it out thousands of times, each time with slightly different inputs, and ships the cheapest drawing. The search is three nested levels, all deterministic, with no randomness anywhere.

The search rests on one fact: a drawing is a pure function of (row, pins). A row is one setting of four whole-chart knobs for sizing. A pin is one recorded decision that phases 1 to 3 must honour: hold a state at a rank, or make a route leave by a given face. There are seven kinds of pin (SearchPins): rank, cut, reverse, face, orient, side and fold. Pins are inputs to layout, not patches to its output. So trying a move means laying out again with one more pin, and undoing it means laying out with the pins held before. There is no transaction and no rollback. Pins name states and transitions by id, never by node index: chaining renumbers nodes, and an undo keyed by node silently did nothing.

The same fact gives a counterfactual. scav dump --layout prints what a drawing rests on, for example --portfolio-row 0 --rank 11:1 --rank 0:0 --reverse 1:0 --face 3:0:1:0 --orient 2 for brew. --no-search with those flags reproduces the drawing exactly. Edit one flag to get the drawing a reader wants, then score it on the shipped objective. If it comes out cheaper, the search lacks a move. If it comes out dearer, the objective is wrong.

Level 2: sixteen rows

Level 2 is a fixed table of 16 rows. Row i is the profile with four bits of i flipped:

Row 0 is the profile as given. The 16 rows are laid out in parallel on the thread pool, each row's layout single-threaded inside it. Every row is scored under the caller's profile, so all rows compare on one scale. If row 0 is not viable, the run fails.

Every viable row is searched to convergence, through Level 1, kicks and the refold search. The pick is argmin(converged cost), with ties going to the lower row. Picking by starting cost is wrong. On bottler, the row with the best start (125,283) converges to 77,441. Row 0 starts worse (154,348) but converges to 51,281; the row with the best start ends 51% dearer.

Level 1: steepest descent over pins

The incumbent is the current best (row, pins) and its cost. A round of Level 1 lists every move the incumbent allows. Each candidate is the incumbent's pins plus one more, laid out through phases 1 to 3 and scored exactly. The round scores all of them in parallel, then reduces in enumeration order and takes the single best strictly improving move. Ties go to the earliest index. A candidate that is not viable, or that needed the spacing inflation retry, is never taken. Taking a move appends its pin and lays out the new incumbent. The search stops when a round is empty or nothing in it improves.

The budget is one counter per move kind, each capped at portfolio_k = 1,024, cumulative over the whole search. The search runs while any counter is under budget. The counters are separate because one shared budget let the first-enumerated kind starve the others: on axis, cuts then ranks under one shared budget of 24 reached 12,702, while separate counters reached 9,940. A face move whose pin cannot change the route is charged to the budget but not scored, since it would draw the incumbent exactly.

Kicks: iterated local search

Greedy descent stops in the first basin it finds. Some structural choices only pay off once the search has adapted to them. On estop, when kicks were built, the right reversal scored 3,218 alone, worse than the incumbent's 3,073, so a strictly improving pass never took it; accepted and searched on, it reached 1,502. (Those are the numbers of that day's objective; the drawing ships today at 906.) Simulated annealing's uphill moves were rejected because there is no temperature to calibrate. Instead, a kick applies a perturbation, searches to convergence, and keeps the result only if the converged cost is cheaper.

  • Kick kinds. Reversal: reverse each cyclic segment not already reversed. Orient: turn a frame of two or more ranks to run down the page. Fold: flip whether a frame of two or more ranks is drawn folded, if it has no fold pin. Orient and fold are allowed only in rounds "with turns".
  • Each kick takes a warm start: the incumbent's pins minus the kicked frame's rank, cut, face, side and fold pins, keeping reversals and orientations. It adds the kick's pin and runs a Level 1 search scoped to that frame. All kicks of a round run in parallel.
  • Round reduction. For each frame, keep its best kick that strictly beats the incumbent, and note the best overall (single). If two or more frames have winners, together puts every winner on one warm start, searches the union of their frames, and is taken if it beats single. Otherwise single is taken, and then each other frame's winner, cheapest first, is rested on top: searched again on the new incumbent and taken if it still improves. Rounds repeat until no kick improves. One unscoped settle search finishes.
  • Two schedules run from each row's converged drawing. A allows turns from the start. B runs reversals alone until they converge, then allows turns. B is kept only if strictly cheaper. Neither dominates: A alone shipped ota a third dearer, and B alone gives up toolchanger's 7,824 → 7,620.
  • Which rows. Every viable row kicks, in parallel, except a row whose converged drawing equals an earlier row's (same t0, t2, state rectangles and route points).

Refold, argmin and the search memo

After the kicks, a refold search runs Level 1 again from every viable row's pins, with fold-cut moves added. A row keeps the result only if it is strictly cheaper. The run then ships argmin over the rows' converged costs.

A Level 1 search is a function of its inputs: the objective, the row's knobs, the budget, the refold flag, the start pins in order and the scope. The search memo stores whole searches by exactly that key (up to 224 words, under one mutex, shared by the pool for one run). A hit returns the pins and cost the search reached, and lays the drawing out again from those pins. Traced runs bypass it.

Where the gain comes from, summed over the corpus (no text / real text): the Level 2 pick before any search gives 5.2% / 2.6% of the total improvement; Level 1 from every row gives 64.6% / 68.3%; kicks and settling give 30.2% / 28.9%; the refold search gives 0.0% / 0.1% (only axis). CPU goes the other way: kicks take about 87–89% of it. Searching to convergence instead of a budget of 24 moves cut Tier 2 by 36.7% at no text and 27.4% at real text, and reader-visible audit defects fell from 60 to 46.

What was tried and rejected

  • In-rank order moves. Adjacent swaps (transpose) improve nothing on any frame: phase-1 crossings read 0 where routed crossings read 87. Readers' crossings happen between routes, not ranks.
  • Screening rows by a short search and finishing only the best: it dropped brew's best row, whose canvas was 38% smaller. Every row is finished.
  • Turns and fold flips as greedy moves led into worse basins (a turn made ota 18% dearer; a fold took tcp 2,685 → 3,493). They are kicks instead.
  • Kick shortcuts, each measured to lose: capping a kick's depth, keeping a kicked frame's pins, screening kicks by starting cost, skipping stale kicks, folding the facing flips into the pins, deduplicating rows at the start.
  • A frame-mirror move: it reflected the wrong axis on folded frames, cost 15% more evaluations on mill, and took tcp to a basin 36% larger.
  • A sound lower bound inside the search prunes nothing, because neighbours are near-ties. (The label bound in the next section works because it bounds only the label half.)
  • Random restarts of a constructive heuristic do about 2,000× worse than guided search at equal CPU (Martí and Laguna), and generate-and-test metaheuristics manage only 6–54 candidates a second.
