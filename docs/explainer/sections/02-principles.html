Principles

The rules everything else obeys

A drawing is a pure function of the chart, the space requests and the profile, computed in integers on a fixed grid. The same inputs give the same bytes, whatever the compiler, the platform or the thread count.

A pure function

Layout is a function of (model, space requests, profile) and nothing else. There is no quick or polish mode, no warm start from a previous layout, no persisted cache and no hysteresis. scav does keep memos, but a memo is not a cache in that sense. Every memo is keyed on every value the step reads, compared whole, so a hit returns exactly what the computation would have returned. It changes the wall clock and nothing else, like the thread count.

Stability comes from construction, not from a cost term. Each stage preserves order, every tie is broken by a total order, and document order drives reading order. The limit is stated plainly: a one-state change can still flip a choice and cascade through the drawing. The remedy is an author's pin or hint, not a memory of the last layout. Earlier designs had a stability weight, a prior layout and dirty regions, and all were removed for this reason.

The integer grid

All layout arithmetic is integer. Coordinates are in grid units of 1/16 pt, a compile-time constant. Coordinates are int32 and products int64. The domain is symmetric, |x| ≤ COORD_MAX = 219 − 1 = 524,287, so negating, taking abs or mirroring cannot overflow. Space requests and spacing fields are capped at COORD_MAX / 4 because the box formula adds several of them. Rectangles are half-open, [x0, x1) × [y0, y1), and output is root-absolute, applied as one final pass. <cmath> is banned in layout, because libm differs between platforms. Square roots are an integer isqrt, ratios are compared by cross-multiplying, and an intersection test is four orient2d sign checks, never a constructed point.

The 2,000-state stress chart measures 167,194 × 109,253 grid units under the real font, about 3× inside the domain. If real charts ever outgrow it, the grid goes to 1/8 pt rather than widening the integers.

The determinism contract

"Layout output is a function of the C++ abstract machine, not of any implementation." Any conforming C++20 toolchain must produce the same bytes. The evidence matrix is six toolchain triples (clang, gcc and MSVC over libc++, libstdc++ and the MSVC STL, on macOS, Linux and Windows) × Debug, Release and a test build × 1, 2, 3, 5, 8, 13 and 16 threads. Odd and prime thread counts are mandatory, because they expose reduction-order bugs that powers of two hide.

  • The thread count never reaches the output. Work is cut into shards whose count depends only on the model: clamp(bit_ceil(ceil_div(entities, 64)), 1, 256). One process-wide pool runs them, and the first free thread claims the lowest unclaimed shard of the deepest open job. A shard writes only its own slot, and reductions merge slots in index order, so which thread ran a shard changes only the wall clock.
  • Reductions are associative, though not necessarily commutative: argmin(value, index) and list append qualify because index order makes them well defined. Saturating addition is banned because it is not associative.
  • Every comparator is a total order ending in a stable key derived from the input: "ties are forks". Any sort that reaches the output is a vendored stable merge sort; std::sort is banned in layout.
  • Randomness, where any is used, is stateless and addressed by position: rnd(seed, phase, item, step). Its only consumer is a test-only delay injector. The search uses no randomness at all.
  • A closed list of banned constructs: types whose width varies (int, long, size_t in value computation), std::hash, iterating unordered containers (scav's HashMap has no begin(), so doing so is a compile error), pointer-keyed containers, <random>, raw / and % on possibly negative values, <cmath>, hashing structs with padding, locale-aware formatting, bitfields, out-of-range shifts and unchecked narrowing.

Two measurement scales

scav's numbers come in two scales, and they are never compared across. No-text means no space requests at all: every state at its minimum size and no labels. The committed cost goldens (corpus_cost.txt) and the unit tests use it. Real text means text measured with the bundled font: this is what scav render, scav dump --layout, the audit tool and corpus_cost_measured.txt use, and what every other drawing on this page shows. The two scales lay out different problems. Text widens states and gaps, label terms are zero under no-text, and the search lands on different pins. A number carried from one scale to the other checks nothing.

Two rules from review"What is trivially right is construction, not search": a straight line beats a kinked one, a start state sits beside the state it enters, and a route never runs along a border. These are built in, not left for the search to discover. And "every rule gets an isolated test on a trivial layout": each rule is held by a chart small enough to name every route.
