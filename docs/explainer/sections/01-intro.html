Introduction

What scav is

scav authors, lays out and renders Harel statecharts: given a chart as text, it boxes every state, routes every transition at right angles and places every label, with the same bytes on every machine.

No existing tool lays statecharts out well. They fail on what a statechart has and a flowchart lacks: transitions that cross the borders of nested states. ELK's default hierarchy handling (SEPARATE_CHILDREN) drops an edge that skips a containment level, with no route and no warning. Its fix, INCLUDE_CHILDREN, lays the whole subtree out in one run and loses each subtree's own direction and aspect ratio; ELK's maintainer calls it "generally a little bit buggy". PlantUML, whose files scav replaces, has no holistic layout: it lays each composite out on its own and attaches the transitions that leave it afterwards, so its splines cut diagonally across the drawing and through submachine boxes. It cannot express a transition from any concurrent region but the first to a state outside the composite, so it refuses tcp.scav. Mermaid documents the limitation, itemis CREATE deleted its auto-layout, and Stately declares layout a non-goal. Of about twenty tools surveyed, none publishes a statechart layout algorithm.

scav's answer is decomposition: it cuts every transition at each border it crosses into segments, joined by ports on those borders. Each submachine is then an ordinary flat graph, ordered on its own, and a long transition still lands in the right place because its pieces are tied to the borders they cross. Earlier tools get one of these two properties, never both.

The model

A state may hold submachines, each holding more states. A state with one or more submachines is a composite; with two or more it is concurrent, and its submachines, informally regions, run at the same time and are drawn side by side with a dashed divider. A submachine that no state owns is a document root.

Every state has a kind: Normal, Initial, Final, Choice, Junction, Fork, Join, History or DeepHistory. All but Normal are pseudostates. Initial and final are written only as *: trans * -> X creates an initial in X's submachine, and trans X -> * a final. Layout treats a pseudostate as a small box at the profile's minimum for its kind. On the shipped readable profile that is 224 × 224 grid units (1/16 pt) for an initial or final, 320 × 320 for a choice, and 64 × 960 for a fork or join bar, upright because ranks run left to right.

A transition joins any two states in the tree. One whose ends lie in different submachines is hierarchy-crossing; ELK calls it a short hierarchical edge if it crosses one containment border and a long hierarchical edge if it crosses more. A transition between two regions of one concurrent state is drawn as a direct arrow, not up through the parent: scav draws topology, not execution paths.

The model is flat arrays of plain records linked by ordinal, not a graph of objects. Each record notes the statement and include it came from, so any drawn primitive traces back to its source bytes, as the figure above shows.

Transition kinds

A transition's kind (external, internal or local) is a layout input: it decides whether the arrow crosses the source's border.

kindthe source's bordera self-transition
external (the default)crosseda loop outside the box
internalnot crossed: the route starts on the border's inner faceno route: the application draws it as text in room it reserves in the state's text bands, as brew does with pressure adjust
localas internal at the sourceno route

When the destination encloses the source (Idle -> On from inside On), the route ends on On's inner face whatever the kind.

The .scav format

  • Terse, keyword-led, LL(1) and whitespace-insensitive. Commas separate every item. The unnamed string after a state or transition is its label.
  • * means initial or final depending on which side of the arrow it is on. s, m and t are aliases for state, submachine and trans, and print back in full.
  • States written directly inside a state's block belong to an unnamed submachine 0. A named block, submachine water { … }, makes one region of a concurrent state.
  • Paths are /-separated and resolve innermost-outward. :name picks a submachine, as in Brewing:water/Heating or arm/Moving:travel/Cruising.
  • include "axis.scav" as arm creates one state arm whose submachine is the included document's root. Including a file twice gives two independent copies.
  • There is one canonical printer, scav fmt. JSON is an output projection, not a format.

Layout is a library

scav is a toolkit, not a framework. It owns the model, the layout, and what layout and drawing must agree on: the draw list, space requests and text metrics. It does not own appearance, composition or the render loop. Its main user is a build system: scav render in a docs pipeline, scav fmt --check, scav check. An editor or game tool links the same pieces and supplies its own drawing back end. The interface is a flat extern "C" ABI with five opaque handles, plain structs passed with their sizeof, no callbacks, and routers chosen by name. It ships as one shared object, libscav, with Python bindings generated from the extracted ABI.

Layout's only inputs are the model, three integer tables of space requests, and a profile of 52 integer settings. It never sees a font or a string. The tables are:

  • BoxSpace{min_w, h_before, h_after} per state and per submachine: the width its text needs, and the bands above and below its children where the name and internal transitions go.
  • PathClear{src, dst} per transition: how far to shorten each end, room for the arrowhead.
  • PathBox{subject, w, h, order}, zero or more per transition: a box layout slides along the route: a label.
  1. The application measures its content with scav's text metrics and fills the three tables.
  2. scav_layout_run validates the profile and the tables (it rejects bad input, never clamps it), lays the chart out, and writes geometry columns (scav.geom.state, route, point, portslot, …) plus one placed rectangle per PathBox.
  3. The application builds a draw list from those columns, optionally with scav's reference builder.
  4. It renders the draw list with scav's SVG back end or its own.
ScaleThe design target is 2,000 states, 5,000 transitions and nesting 16 deep. This page draws on a corpus of eleven hand-written charts, from the 3-state estop to bottler, which nests six levels and sends faults from its innermost valve straight to the root.
