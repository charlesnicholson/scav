Introduction

What scav is

scav lays out and renders Harel statecharts: every state boxed, every transition routed at right angles, every label placed, identical bytes everywhere.

Existing tools fail on what statecharts have and flowcharts lack: transitions that cross the borders of nested states.

  • ELK either drops an edge that skips a containment level, or lays the whole subtree out in one run and loses each subtree's own direction and aspect.
  • PlantUML, whose files scav replaces, lays each composite out alone and attaches leaving transitions afterwards, so its lines cut through boxes; it cannot express tcp.scav at all.
  • Of about twenty other tools surveyed, none publishes a statechart layout algorithm.

scav's answer is decomposition: every transition is cut at each border it crosses into segments, joined by ports. Each submachine becomes a flat graph laid out on its own, and a long transition still lands in the right place because its pieces are tied to the borders.

The model

  • A state may hold submachines of further states. With one or more it is composite; with two or more it is concurrent, and its submachines (regions) run together, drawn side by side with a dashed divider.
  • Every kind but Normal is a pseudostate: initial, final, choice, junction, fork, join, history, deep history. trans * -> X creates an initial and trans X -> * a final. Layout draws a pseudostate as a small box at its kind's minimum size: on the readable profile, 224 × 224 grid units for initial or final, 320 × 320 for a choice, 64 × 960 for a fork or join bar.
  • A transition joins any two states. If its ends lie in different submachines it is hierarchy-crossing. A transition between two regions of one state is drawn directly, not through the parent: scav draws topology, not execution paths.
  • The model is flat arrays of records, each traceable to its source statement.

Transition kinds

A transition's kind decides whether its arrow crosses the source's border.

kindthe source's bordera self-transition
external (default)crosseda loop outside the box
internalnot crossed: the route starts on its inner facea loop inside the box
localas internala loop inside the box

When the destination encloses the source, the route ends on the destination's inner face, whatever the kind.

The .scav format

  • Keyword-led, LL(1), whitespace-insensitive; commas separate items; an unnamed string after a state or transition is its label. s, m and t abbreviate state, submachine and trans.
  • States written directly in a state's block form an unnamed submachine; submachine water { … } names one region.
  • Paths are /-separated and resolve innermost-outward; :name picks a submachine, as in Brewing:water/Heating.
  • include "axis.scav" as arm makes a state arm holding the included document; each include is an independent copy.
  • scav fmt is the one canonical printer. JSON is an output, not a format.

Layout is a library

scav owns the model, the layout, and what layout and drawing must agree on: the draw list, space requests and text metrics. The application owns appearance and the render loop. The interface is a flat extern "C" ABI with no callbacks, shipped as libscav with Python bindings; its main user is a build system running scav render, scav fmt --check and scav check.

Layout's only inputs are the model, a profile of 52 integer settings, and three tables of space requests. It never sees a font or a string.

  • BoxSpace, per state and submachine: the width its text needs, and four bands around its children: above, below, before and after.
  • PathClear, per transition: the least length of each end leg, for the arrowhead.
  • PathBox, zero or more per transition: a label box to place along the route.

The application measures its text with scav's metrics, fills the tables, and calls scav_layout_run, which rejects bad input rather than clamping it. It draws the returned geometry with scav's SVG back end or its own.
