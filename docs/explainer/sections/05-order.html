Phase 1

Ordering: which rank, which slot

Phase 1 gives every node in a frame a rank, its column, and a slot within that rank, reading only pins, label sizes, the line height and sweep_count.

A frame's graph has three kinds of node: a state node for each live child state, in document order; a boundary node for each segment end that is a port on the frame's border or an inner face; and the bend nodes chaining adds later. Each segment becomes one edge; an edge whose two ends are the same node, such as an external self-loop, is dropped. Ranks are columns running left to right, and nodes stack down within a rank; rank_sep (576, 36 pt) is the gap between columns and node_sep (288) the gap within one. Disconnected components are ordered separately and packed by phase 2; otherwise every unconnected state would sit at rank 0 in one tall column.

Breaking cycles

Layering needs a DAG, and statecharts are full of cycles. First, Tarjan's strongly-connected-components pass (iterative, roots in node order) marks every segment whose ends share a component as cyclic; only cyclic segments are offered to the search's reverse move.

Then orient_acyclic applies every reverse pin (a ReversePin names a segment to flip) and runs an iterative depth-first search, roots in node order (document order) and each node's out-edges in segment order. An edge into a node still on the stack is a back edge: it is flipped and marked reversed. Only edge directions change; no node moves.

RuleWhich edge of a cycle is reversed is an artefact of declaration order, so the reversal is a search dimension, not a rule.

Ranking by longest path

assign_ranks runs four steps on the DAG:

  1. Topological order by Kahn's algorithm, sources seeded in node order.
  2. Longest path from the sources: in topological order, every edge v → w sets rank[w] = max(rank[w], rank[v] + 1).
  3. Pull right, in reverse topological order: a node that is not a boundary node and has fewer in-edges than out-edges moves to one rank before its nearest successor. A source with three successors therefore sits next to them, not at rank 0.
  4. Sink boundary nodes to the last rank, so exits sit on the trailing border and entries on the leading one; then empty ranks are squeezed out.

Rank pins

A rank pin (RankPin{state, rank}) overwrites one state's rank after ranking. Longest path does not run again, so an edge may end up flat (both ends in one rank) or pointing backward. Initials are never pinned: after the pins, each initial is re-seated one rank before the nearest state it touches, and if that state is at rank 0, every other node moves up one to make room. Then empty ranks are squeezed out. A pin to the rank longest path already chose changes nothing.

Side pins act on ports. A port pinned to a cross border (top or bottom, in a frame running across) holds its edge out of ranking, cycle breaking and the sweeps, and takes its mate's rank, first or last in it. A port pinned to a rank border has its edge oriented so the boundary node is the source (leading border) or the sink (trailing border).

Charges: room the gaps must hold

Before chaining, while each edge still spans its whole rank range, rank_derived charges each rank boundary (the gap after a rank) with the room it must hold:

  • Label charge. An edge crossing one boundary charges that gap its label's width (its PathBox width, or its height in a frame running down). An edge crossing several boundaries is placed afterwards, widest label first: it takes the widest boundary it crosses (ties go to the middle), and costs nothing if that boundary already holds it. An edge inside one rank charges nothing.
  • Lane charge. Per connected component, an edge "turns" in its first boundary and, if it spans more than one, in its last. A boundary where two or more edges turn reserves lanes × line height (269 per lane at readable). This estimate only decides folding; phase 2 recomputes the real lane room.

Textbook label placement adds a dummy node per label. scav widens the gap instead: dummy nodes would double every rank and need a frame to own each label.

Chaining long edges

Every edge spanning more than one rank becomes a chain through one bend node per intermediate rank (chain_long_edges). Bends take part in the sweeps like any node, and the router treats them as hard waypoints. A cut (ChainCut{trans, leg}) leaves the segment as one long edge with no bends, which the router draws freely. Cuts matter: 58 of the corpus's 257 transitions carry a phase-1 bend, and they hold 295 of its 421 kinks (70%).

Crossing minimisation by median sweeps

minimize_crossings starts from document order: in each rank, pinned-first ports, then states, then boundary nodes, then bends, then pinned-last ports. It runs up to sweep_count = 8 sweeps. Even sweeps go down (ranks 1 to R−1, each ordered by the median of its predecessors' positions); odd sweeps go up (ranks R−2 to 0, by the median of successors').

  • median_of sorts the neighbours' positions and takes the upper median, element size/2. A node with no neighbour on that side has no median; it is a fixed barrier that keeps its slot.
  • reorder_rank swaps adjacent nodes while med[i] > med[i+1], strictly, so ties keep their order.
  • After each sweep the frame's crossings are recounted; the best arrangement so far is kept, and sweeping stops as soon as a sweep reaches 0. A frame that starts at 0 is never swept.

Crossings are counted per adjacent rank pair: sort the edges by (north position, south position) and count inversions with a Fenwick tree. Edges that share an endpoint never count as crossing.

Why the medianThe barycenter heuristic has no constant-factor bound (it can be Ω(√n) off); the median has one. Global sifting is a named lever, not built. transpose was built, improved nothing anywhere, and is not in the pipeline; running it inside the sweep loop took the corpus from 0 layered crossings to 7. With sweep_count 0 against 8, routed crossings over the corpus were 99 against 91 (no-text), though axis (2 against 4) and mill (38 against 43) did better unswept.

The sweeps leave little: all 1,154 frames over the corpus, the gauntlet and the 2k targets have zero layered crossings, while the routed drawings of the same charts had 87. The crossings a reader sees come from routing, not ordering.

Orientation and fold pins

An orient pin (OrientPin, applied by a kick) turns a frame to run down: ranks become rows and the axes swap everywhere downstream. A fold pin (FoldPin) passes through phase 1 untouched; it names where phase 2 cuts a long rank run.

What the search can change here

Most of the search's moves land in phase 1: rank, cut, reverse, side and orient pins. In-rank position is not searched: measured, it has no slack. A move re-orders only the frames it touches and copies the rest from the incumbent.

RejectedEades–Lin–Smyth greedy cycle removal: the search chooses reversals instead. dot's edge-weight schedule: deliberately not taken. A warning from scale: on a flat 2k-state chain, DFS reversal can make edges a thousand ranks long, and chaining them makes a million ordering nodes; without wrapping skips that costs seconds instead of 2 ms.
