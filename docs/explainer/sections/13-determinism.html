Proof it holds

Determinism: goldens, hashes and selftest

Three hashes per drawing, committed goldens and a self-test check that the same inputs give the same bytes on every machine.

Three hashes

Every laid-out chart carries three 32-bit xxHash32 digests, computed byte by byte so every machine agrees:

  • Inputs digest: everything that is not geometry (the profile, the router, the packer choice, the space requests). A golden is reproducible only against a stated measurement policy, and this names it.
  • Structural hash: ranks, in-rank orders, port sides and each route's turns, seeded with the model. Ranks are recovered from the rectangles, so it can be recomputed from a finished drawing.
  • Coordinate hash: every rectangle, point and port.

The split localises a change: moving the drawing changes only the coordinate hash, and remeasuring text without reordering changes only the inputs digest and coordinates.

Selftest and thread counts

scav selftest lays every built-in chart out at 1, 2, 3, 5, 8, 13 and 16 threads and compares all three hashes with the embedded goldens. A difference from the golden is a toolchain finding; a difference between thread counts is a sharding defect, since the shards and their merge order never depend on the schedule.

The determinism test compares every geometry column's bytes, the hashes and the chosen Level 2 row across those thread counts, under a delay injector that reshuffles the schedule. It includes the inflation retry and a chart where every row ties, so index-ordered merging decides. Timing never gates a determinism claim.

CI runs six toolchains (clang, gcc and MSVC, on macOS, Linux and Windows) × Debug, Release and a testable build × the thread counts. Odd and prime thread counts are mandatory, because they expose merge-order bugs that powers of two hide. The testable build must match Release byte for byte; with integer arithmetic, any divergence means undefined behaviour.

Goldens

Committed goldens hold the three hashes, every cost term at both scales, the shares, every router's results, and draw-list, dump and SVG output.

How scav is tested

  • Unit tests type inputs in as plain structs: no disk, no parsing, no earlier stage, so a defect fails one test, not a hash three stages away.
  • The gauntlet: 31 one-element charts, small enough to name every route, held to reader-visible properties (no route through a box, every route axis-aligned and reaching its ends) on what actually ships. A property that does not hold yet is carved out with a pinned count.
  • Every rule gets an isolated test on a trivial layout, every fixed bug leaves a test, and every optimisation has a test mode.
  • Also golden, property, sanitizer, fuzz, Python binding and baseline tests. Performance tests assert floors, never times.

The trace lists layout's decisions (rank assigned, edge reversed, candidate scored and so on). It forces one thread and replays the winning (row, pins), and traced runs hash the same as untraced ones. The figures marked "from the trace" read it.
