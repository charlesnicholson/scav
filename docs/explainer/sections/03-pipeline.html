Overview

The pipeline at a glance

Four phases, decompose, order, size and route, turn a chart into a drawing, followed by labels and a cost; a search reruns all but decomposition hundreds of thousands of times with different choices and keeps the cheapest result.

Each phase is its own translation unit and hands the next a plain struct declared in its header; none of these crosses the ABI. A phase reads the chart for containment and liveness but never for something an earlier phase computed, so a unit test can type a phase's input in directly: a SubmachineOrders with three ranks is nine integers.

One pass from ordering through cost, for one setting of the search's choices, is a candidate. Phase 1 reads no extents from the profile, only sweep_count, the line height and the label sizes, so its first run is hoisted: it runs once per layout under the caller's profile and is shared by all 16 Level 2 rows and every inflation retry. A candidate with a new pin (a choice the search fixes, such as a state's rank or the face a route leaves by) re-derives every phase the pin reaches and copies every frame whose inputs did not change.

The search around it

  1. Validate the profile, the space tables and the router name, and reject on failure.
  2. Decompose once, and order once.
  3. Level 2: lay out 16 rows in parallel, each a whole-chart setting of four phase-2 knobs (whether the packer also tries a one-row box packing, whether packing compacts, which aspect each frame packs toward, whether long rank runs always fold).
  4. Level 1 from every viable row: steepest descent over pins, one move per round, until no move improves.
  5. Kicks: structural changes (reverse a cycle edge, turn a frame to run down the page, flip a fold), each searched to convergence and kept only if it ends cheaper. Then a refold search.
  6. Take the cheapest row (ties go to the lower row), and write the geometry columns, placed labels and diagnostics.

On mill, the largest corpus chart, one layout scores about 1.6 to 1.9 million candidates; the search and making it fast explain how.

When routing fails: the inflation retry

Inside a candidate, if routing finds a net unreachable, the inflation retry widens the spacing and runs phases 2 and 3 again from the same ordering, up to 8 times. Whatever still fails is drawn as a straight line with a RouteDegraded diagnostic, and the run still succeeds.

Where a candidate's time goesOn mill with no text, one candidate took about 145 µs at one measured commit: ordering 17, sizing 42, routing 55 and cost 30. Real text adds about 94 µs of label placement.
